# Kaspi API Watcher

Следит за документацией API Магазина на Kaspi.kz в [Kaspi Гид](https://guide.kaspi.kz/partner/ru/shop/api/orders), собирает из неё **OpenAPI 3 (Swagger)** и присылает в Telegram сообщение о том, что именно изменилось. Заодно выкладывает готовую страницу со Swagger UI на ваш хостинг по FTP.

Документация в Гиде живёт в виде вопросов и ответов: ни changelog'а, ни машинночитаемой схемы там нет, а примеры запросов приходится собирать глазами. Watcher делает из этого схему и следит за правками.

## Возможности

- **Один GET-запрос на раздел.** Браузер и headless-хром не нужны: сервер отдаёт все вопросы раздела в JSON внутри страницы (`<script id="__NUXT_DATA__">`, формат devalue), парсер распаковывает его сам.
- **OpenAPI 3.0.3 из примеров.** Пути, методы, query- и path-параметры, заголовки, тела запросов и ответов, описания и значения из таблиц документации — всё выводится из примеров запросов и ответов.
- **Уведомления по делу.** Не «что-то обновилось», а списки добавленных, изменённых и удалённых вопросов со ссылками плюс текстовый дифф: видно построчно, что переписали.
- **Публикация на хостинг.** Одностраничный HTML со Swagger UI, внутрь которого зашита свежая спецификация, заливается по FTP или FTPS. Рядом кладётся `openapi.json` для Postman и Bruno.
- **Без зависимостей.** Только стандартная библиотека Go, включая собственный FTP-клиент. `go.sum` в проекте нет и не будет.

## Сборка

Нужен Go 1.21 или новее, зависимостей нет.

```bash
go build -o kaspi-watcher.exe .   # Windows
go build -o kaspi-watcher .       # Linux, macOS
```

## Быстрый старт

Конфигурация — это скрипт запуска: он выставляет переменные окружения и вызывает бинарник. В репозитории лежат пустые шаблоны, свою копию заполняете локально.

### Windows

```bat
copy run-example.bat run.bat
run.bat
```

> **Правьте `run.bat` редактором, который сохраняет переводы строк CRLF.** С переводами строк в стиле Unix (LF) `cmd` спотыкается о русские комментарии: кириллица в UTF-8 занимает два байта, парсер теряет позицию в файле и начинает выполнять обрывки комментариев как команды. В VS Code текущий режим виден в правом нижнем углу. В репозитории это зафиксировано через [.gitattributes](.gitattributes), так что после клонирования файл получит правильные переводы строк сам.

### Linux и macOS

```bash
cp run-example.sh run.sh
chmod +x run.sh
./run.sh
```

### Дальше одинаково

Откройте свою копию, заполните токен бота, id чата и, если нужна публикация, доступы к FTP. Первый запуск создаст снимок и напишет в Telegram, сколько собрано вопросов; дальше сообщения приходят только при изменениях.

```bash
./run.sh -interval 60    # работать самому, проверка раз в час
./run.sh -dry-run        # ничего не отправлять и не заливать, всё в консоль
```

> **`run.bat` и `run.sh` держите вне репозитория** — в них оказываются токен бота и пароль от FTP. Оба перечислены в [.gitignore](.gitignore); в репозитории только шаблоны [run-example.bat](run-example.bat) и [run-example.sh](run-example.sh).

## Автозапуск на Linux

Два рабочих варианта — выбирайте любой, но не оба сразу.

**cron**, если проще держать расписание снаружи. Программа делает один прогон и выходит, `-interval` не нужен:

```cron
0 * * * * /opt/kaspi-watcher/run.sh >> /var/log/kaspi-watcher.log 2>&1
```

**systemd**, если хочется, чтобы процесс жил сам и поднимался после перезагрузки. Здесь расписание внутри программы, поэтому `-interval`:

```ini
[Unit]
Description=Kaspi API Watcher
After=network-online.target

[Service]
ExecStart=/opt/kaspi-watcher/run.sh -interval 60
WorkingDirectory=/opt/kaspi-watcher
User=kaspi
Restart=on-failure
RestartSec=60

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now kaspi-watcher
journalctl -u kaspi-watcher -f
```

Логи пишутся в stderr, так что в cron их нужно перенаправлять самому, а в systemd они попадают в journal. Скрипт сам переходит в свой каталог, но если данные должны лежать в другом месте — раскомментируйте `KASPI_WATCH_DIR` в `run.sh` и укажите абсолютный путь.

## Настройка

Всё задаётся переменными окружения (для этого и нужен `run.bat` или `run.sh`) либо одноимёнными флагами; флаг перебивает переменную.

### Telegram и данные

| Переменная | Флаг | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | Токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | — | Id чата или канала |
| `WEBHOOK_URL` | — | Необязательно: webhook Slack, Discord или Mattermost |
| `KASPI_WATCH_DIR` | `-dir` | Папка для данных, по умолчанию `./kaspi_watch` |
| `MERCHANT_UID` | `-merchant-uid` | Код магазина — подставится в схему примером к заголовку `X-Merchant-Uid` |

### Публикация на хостинг

Оставьте `FTP_HOST` пустым — публикация просто не будет выполняться, остальное продолжит работать.

| Переменная | Флаг | Назначение |
|---|---|---|
| `FTP_HOST` | `-ftp-host` | Хост, можно с портом: `ftp.example.kz` или `ftp.example.kz:21` |
| `FTP_DIR` | `-ftp-dir` | Каталог на хостинге, например `/public_html/kaspi`. Создаётся сам |
| `FTP_FILE` | `-ftp-file` | Имя html-файла, по умолчанию `kaspi-api.html` |
| `FTP_USER` | `-ftp-user` | Логин |
| `FTP_PASS` | `-ftp-pass` | Пароль |
| `FTP_TLS` | `-ftp-tls` | `off` (по умолчанию), `explicit` (AUTH TLS) или `implicit` (порт 990) |
| `FTP_INSECURE` | `-ftp-insecure` | `1` — не проверять TLS-сертификат хостинга |
| `FTP_UPLOAD_JSON` | `-ftp-json` | Класть рядом с html и сам `openapi.json`. По умолчанию да |
| `FTP_ALWAYS` | `-ftp-always` | Заливать каждый прогон, даже если ничего не изменилось |
| `PUBLIC_URL` | `-public-url` | Адрес получившейся страницы — придёт ссылкой в уведомление |

### Остальные флаги

| Флаг | Назначение |
|---|---|
| `-sections orders,goods` | Разделы API через запятую. Появится новый — подключается без правок кода |
| `-interval 60` | Работать в цикле, проверка раз в N минут. `0` — один прогон, для планировщика |
| `-dry-run` | Ничего не отправлять и не заливать, печатать в консоль |
| `-from ./pages` | Читать `orders.html` и `goods.html` с диска вместо сайта |
| `-exit-code` | Код выхода 1, если были изменения — для CI |

## Что появляется в папке данных

```
kaspi_watch/
├── openapi.json                 актуальная схема (editor.swagger.io, Postman, Bruno)
├── snapshot.json                снимок всех вопросов, с ним сравнивается следующий прогон
├── published.json               версия, уже залитая на хостинг — чтобы не гонять файл впустую
└── history/2026-09-12_14-39-52/
    ├── diff.txt                 полный дифф изменения
    ├── prev_openapi.json        схема до изменения
    └── prev_snapshot.json       снимок до изменения
```

## Как выглядит уведомление

```
🔔 Изменения в документации Kaspi API

Новые вопросы (1):
➕ Я с помощью API добавил товары для продажи. Как узнать результат?

Изменены (1):
✏️ Как с помощью API узнать код категории для добавления товара? (обновлено 12.06.2024)

Удалены (1):
➖ Как узнать погоду через API Kaspi?

--- goods/q3216 (было)
+++ goods/q3216 (стало)
@@ -1,7 +1,7 @@
 # Как с помощью API узнать код категории для добавления товара?
 https://guide.kaspi.kz/partner/ru/shop/api/goods/q3216
-Обновлено: 01.08.2026
+Обновлено: 12.06.2024

-Старая формулировка, которую Kaspi переписал.
+Для этого отправьте API-запрос. Можно использовать любой сервис...
 В ответе вы получите названия категорий и их коды для API-запросов.

📘 Swagger на сайте: http://example.kz/kaspi/index.html
```

Заголовки вопросов в Telegram — кликабельные ссылки на Гид. В сообщение попадают первые 2500 символов диффа, полный текст приходит файлом `diff.txt` вместе со свежим `openapi.json`.

Без диффа приходят только два вида сообщений: стартовое после первого снимка и предупреждения — если сайт недоступен или вёрстка изменилась и вопросов собралось подозрительно мало. Когда изменений нет, в Telegram не уходит ничего.

Сравнение идёт по тексту вопросов из Гида, а не по схеме: правки в самой схеме (заголовки, примеры) уведомление не вызывают, хотя файл и страница на хостинге обновятся.

## Страница на хостинге

Спецификация зашита прямо в HTML, поэтому браузеру не нужны ни CORS, ни правильный MIME у json-файла — страница работает на любом shared-хостинге. Ассеты Swagger UI подтягиваются с CDN.

Файл заливается под временным именем `.part` и затем переименовывается, так что посетитель не поймает наполовину записанную страницу. Недостающие каталоги создаются автоматически, IP из ответа `PASV` игнорируется в пользу того, к которому уже подключены — иначе NAT у хостера ломает передачу.

«Try it out» намеренно выключен: запрос из браузера ушёл бы с вашего домена на `kaspi.kz`, а это cross-origin, и Kaspi таких заголовков не отдаёт. Для настоящих запросов импортируйте `openapi.json` в Bruno или Postman.

## Обязательные заголовки

Оба объявлены в схеме как обычные параметры с `in: header` и `required: true`, поэтому видны в каждой операции и доезжают до клиентов при импорте:

- **`X-Auth-Token`** — токен из кабинета продавца: Настройки → Токен API.
- **`X-Merchant-Uid`** — код магазина. В Kaspi Гид он не описан, но обязателен: в одном кабинете может быть несколько магазинов, и сервер должен понимать, про какой спрашивают.

Настоящий токен в схему не попадает никогда — она выкладывается на хостинг открыто, поэтому в примере всегда стоит подстановка `{{token}}`. Для `X-Merchant-Uid` подставляется значение `MERCHANT_UID`, а если оно пустое — `{{merchantUid}}`: пустой обязательный заголовок хуже отсутствующего, он перекрыл бы значение, заданное на уровне коллекции.

## Импорт в Bruno

1. Import Collection → OpenAPI V3 Spec, выбрать `openapi.json`.
2. Завести Environment с переменными `token` и `merchantUid` — оба заголовка подставятся во все запросы.

Импорт делает разовый снимок файла: после обновления схемы коллекцию нужно импортировать заново.

Известное ограничение Bruno: медиа-тип `application/vnd.api+json` при импорте сводится к обычному `json`, и в запрос уходит `Content-Type: application/json`. Если операция v2 ответит 415, допишите заголовок вручную — на уровень коллекции его выносить нельзя, у `/api/products/import` тело `text/plain`.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Были изменения, если указан `-exit-code` |
| 2 | Ошибка: сайт недоступен, не разобралась страница, не записались файлы |
| 3 | Вопросов собралось подозрительно мало — снимок не обновлён, вероятно изменилась вёрстка |

## Тесты

```bash
go test ./...
```

Покрыто главным образом то, что руками проверять дорого: FTP-клиент гоняется против игрушечного FTP-сервера из тестов — заливка html и json, создание недостающих каталогов, откат с `EPSV` на `PASV`, FTPS с самоподписанным сертификатом и отказ принимать такой сертификат без `FTP_INSECURE`, неверный пароль, режим `-dry-run`. Отдельно проверяется схема: оба обязательных заголовка в каждой операции, отсутствие дублей и экранирование спецификации при вставке в HTML.

## Чего ожидать не стоит

Схема выведена из примеров документации автоматически — это черновик. Типы полей угаданы по значениям в примерах, у большинства операций нет описания ошибок. Сверяйтесь с первоисточником: ссылка на исходный вопрос есть в описании каждой операции и в поле `x-kaspi-guide`.

Если Kaspi поменяет вёрстку Гида, парсер это заметит: при подозрительно малом числе собранных вопросов снимок не обновляется, а в Telegram уходит предупреждение — ложного «всё удалили» не будет.
